# 前平举复测再 0 计数 — 第二轮定量定位与修复（2026-11-07）

真机证据：生产环境、iPhone、Full 模型，用户站立做多组双臂前平举（手臂到肩高、个别过头）
与单臂前举，计数始终 0；诊断自报方向已确认、抬臂 56°/35°、关键关节置信度 64%；整场校准
未完成（进度 42%→26%→13% 回落），计时与计数器在校准期照常运行。

## 角度定义审计（修复前）

- 抬臂角 = `angle(肘, 肩, 同侧髋)`：以肩为顶点、肩→肘与肩→髋两向量的 **3D 夹角**，
  在 MediaPipe **world landmarks**（米、髋中心原点）上计算（`extendedRecognition.ts`
  front_raise 分支）；图像坐标只参与可见性门与 tilt。
- 前向轴 = 肩线 × 躯干轴的叉积、鼻尖定符号（躯干相对坐标，正面/侧身/斜侧身均成立）。

## 复现与归因（三层证据）

1. **完美几何合成轨迹**（已知真值 90°/110°/单臂 90°/侧平举/45° 半程，正面与 ±30° 侧身）：
   旧定义测得 90°→90°、110°→109°，计数与拒判全部正确。**定义与 65–115° 计数门自洽，
   数学层零偏差**——偏小不在公式里。
2. **生产模型实测输出**：用仓库内同一 `pose_landmarker_full.task` 对用户复测视频
   （录屏内嵌画面裁切，VIDEO 模式 8 FPS）跑出 311 帧 world landmarks 回放评估器。
   直臂峰值帧（模型肘角 ≥140°、腕在图像中到达肩线）上：旧肘角通道中位 88°、p25 80°；
   最差帧（t≈46.5 s 左侧）肘向量前向分量仅 +0.149 m（解剖上臂长 ~0.28 m 的 53%）、
   向下分量 +0.056 m，旧公式读 72.9°，同一帧腕矢状角 91.7°。即**模型对朝向相机的
   上臂深度系统性压缩（前向行程只恢复约一半到三分之二）并把肘往躯干方向拽**，
   肘通道单帧可量小 ~20°（差侧）；腕向量跨双节段，同等绝对畸变对应的角误差小得多
   （同批帧腕矢状角中位 91°、p25 84°）。
3. **设备端 56°/35° 的读数性质**：诊断面板的「抬臂」是**逐帧瞬时值**，产品没有
   「本组峰值」读数通道；该数值出现在何帧无从复原，不能当作本组最大值的实测。
   本场 0 计数的充分解释是三层叠加：①校准从未锁存（见下），计数根本没有启动；
   ②肘通道量小使部分峰值帧跌破 65°；③部分次数肘弯曲明显（录屏可见前臂竖起式抬法），
   肘角 ≥140° 的形态门独立拒判。①是代码级确定缺陷，②有实测数字，③为录屏观察。

## 修复（角度）

- 抬臂角改测**肩→腕向量在躯干矢状面（躯干下行轴 × 前向轴）内的投影角**：
  `atan2(腕向·前向, 腕向·下行)`。完美几何下与旧定义同读真值（90→90、110→110、
  130→130），计数门 **65–115° 不动**；方向门（逐侧前向主导）一字未改；形态仍由
  肘角 ≥140° 把守——腕线只在手臂近伸直时代替上臂方向。
- 侧平举现在双重失败：腕向量几乎无矢状面投影（读数 ≈0–30°）且非前向主导。
  斜向前举（前向主导）矢状角 ≈ 真屈曲角，照常计数；45° 半程照常拒判。

## 修复（校准锁存 + 计时）

- 校准改**累积锁存**：起始姿势保持时间跨帧累积，非起始帧只暂停不清零
  （旧行为：任一非起始帧把 2 秒计时清零，实测进度 42%→26%→13% 回落）；
  累计满 2 秒即 `ready` 并保持，只有真实跟踪丢失（interrupt）才清累积。
  baseline 的置空/更新行为未动。
- 计时：Workout 页会话时钟在**本页首次校准完成前冻结**（`useSessionClock` 的
  frozen 入参并入 `!calibratedOnce`），校准完成后闩锁放行；其后跟踪丢失再校准
  不再冻结（与暂停恢复语义一致）。服务端 effectiveSeconds 累积语义未动——
  这是本轮取的最小等价实现：用户在校准完成前看到的计时不动、明确知道还没开始计数。

## 未尽事项（不冒充已解决）

- 离线回放用的是录屏内嵌画面（分辨率、裁切与设备原始相机流不同），只能证明
  机制与量级，不能替代真机复测；本轮修复的最终验收仍是 Edward 真机：
  站立双臂至肩高应计数、诊断读数应回到 ≈90°。
- 若真机仍出现成组 0 计数，下一排查点是肘角 ≥140° 形态门与本人抬法（前臂竖起式）
  的匹配问题——那是产品标准问题，不应再用放宽角度测量来掩盖。
