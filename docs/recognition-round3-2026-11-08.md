# 识别第三轮：校准存活、对称峰对峰、稳定性持续性聚合（2026-11-08）

真机证据（Edward 2026-11-08 宿舍复测，同日两场）：

- **前平举**：站立做双臂 + 单臂前平举 70 余秒，计数始终 0。录屏中起始姿势校准进度
  最高到 46%，随后回落到 27%——开场头部被画面上沿裁掉、抬臂时手腕贴近画面边缘、
  中途一次侧身，三类事件都在反复清零校准。
- **锤式弯举**：视觉上对称的双臂弯举，两组分别打出对称 45（慢组）/ 32（快组）、
  稳定性 38（慢组）/ 64（快组）。节奏越快对称越低、节奏越慢稳定性越低——两个方向
  都指向聚合方式，而不是动作本身。

本轮三处修复都只动「聚合/存活」层：**全部阈值与计数门一字未动**（260°/s、×0.08、
上臂 15°、×1.5、峰差 1.5/°、peakOther 1.2/°、峰值肘角 ≤80°、放回 ≥145°、校准
2000ms、合并窗 150ms、pending 等待 600ms 均保持）。

## 1. 校准在瞬时门中断下存活（front_raise 等 legacy 路径）

根因：front_raise 不在 adaptive 名单内，走 `ExtendedExerciseTracker` legacy 路径；
其 `update()` 的五道门（无效帧 / 帧间隔 >750ms / 必需关节可见度 <0.25 或出界 /
平滑可见度 <0.55 / `measure()` 返回错误串）此前全部调用 `interrupt()`，而
`interrupt()` 把 `calibrationBank` 清零、`ready` 置假。第二轮的「进度锁存」只在
能测量的非起始帧之间成立（暂停不回退），门一触发就全额回退——真实房间里摆位、
转身、试抬手臂都会触发门，于是校准永远攒不满 2 秒。

修复（`extendedRecognition.ts`）：

- `interrupt()` 新增可选参数 `{preserveCalibration, preserveReady}`：保留校准时，
  bank、进行中的保持段、校准基线保留（基线是校准状态的一部分，per-side 更新器
  在 ready 后无条件解引用它）；`preserveReady` 额外保留已锁存的 ready。
  会话级调用方（暂停/结束、AdaptiveRecognition 的 interrupt）不传参，行为与
  此前完全一致（硬中断）。
- 五道门里四道**瞬时可见性门**（无效帧、帧间隔、必需关节、平滑可见度）改走
  `softInterrupt`：bank + 保持段 + ready 全部保留，ready 一旦锁存，本场内不再
  被瞬时门打掉。
- `measure()` 的**形态拒判**（错误串）改走 `formInterrupt`：只保留 bank + 保持段，
  **不保留 ready**。拒判串里多条明确要求重新校准（「请重新保持起始姿势校准」
  「请稳定后重新校准」），且站立后勾腿的换腿拒判证明：若 ready 保留，平滑过渡帧
  会把被拒的换侧动作拼成一次假计数。校准进度不丢，重新保持即可在 bank 之上
  补满，不必从 0 开始。
- **过期守卫**：未 ready 时，若超过 10 s 没测到起始姿势帧（`CALIBRATION_STALE_MS`），
  bank 与保持段清空——防的是用户攒了 50% 后离场一分钟再回来续攒。`softInterrupt`、
  `formInterrupt` 与校准段本体三处都检查（以最后一次起始姿势帧时间 `lastStartAt`
  为准）。

## 2. 单侧对称改峰对峰（锤式弯举 + 前平举）

根因：两侧峰窗重叠（±150ms）才合并为双侧一次；不重叠时各侧单独成次，对称按
`peakOther`（本侧峰值瞬间另一侧的瞬时角度）打分。双臂只是松散同步时，另一侧在
该瞬间正处半程（2 s 节奏、350 ms 偏移时肘角 ≈100°），对称被打到 ≈50；节奏越快
偏移占比越大，分越低（45 → 32 与此机制吻合）。

修复：tracker 记住每侧最近一次确认峰（`lastPeak`：峰窗中点时刻 + 峰值）。
单侧成次时，若另一侧在 **800ms** 内也有确认峰——来源可以是它的完成记录
（`lastPeak`），也可以是它尚未关闭的周期里已确认的峰（pending 先于对侧完成
被冲刷时走这条）——对称改为与双侧一次相同的峰对峰公式
`100 − |峰差| × 1.5`。窗口外（真单臂、交替举）保持原 `peakOther` 公式不变：
交替举休息臂在峰值瞬间 fully 伸直（≥150°）时仍得高分；休息臂半弯（95°）的
真单臂仍得 46 分，与修复前逐分一致（测试锁定）。

发射时序覆盖三种情形：①对侧完成晚于本侧但峰窗不重叠——本侧在对侧完成时
发射，对侧峰刚写入 `lastPeak`；②本侧 pending 在 600ms 后被冲刷、对侧尚未
完成——查对侧仍打开的周期峰；③本侧先发射后，对侧成次时反查 `lastPeak` 里
本侧的峰。计数与合并规则未动。

## 3. 稳定性改持续性聚合（锤式 / 前平举 per-side + 通用路径）

根因：稳定性取周期内 `controlMax`（控制惩罚最大值）与 `speedMax`（100ms 窗
角速度最大值）。单帧抖动即可给一整次定罪；周期越长（节奏越慢）最大值爬得
越高——慢组稳定性 38 与此吻合。而实时提示路径早有持续性要求（偏离持续
`UPPER_ARM_SUSTAIN_MS` 才出声），评分路径却没有，两边口径不一致。

修复：新增 `sustainedPeak(spans, fallback)`——取「样本 ≥ v 的连续覆盖 ≥150ms」
所能达到的最大 v。速度窗以其真实时间跨度入账（单个 100ms 窗证明不了 150ms，
连续两个窗可以）；控制逐帧样本先经 `controlSpans()` 展开为零阶保持跨度
（最后一帧的保持时长按前一帧间隔封顶，≤150ms，峰/回程阶段不算移动阶段的
证据）。样本 <3 或没有任何值达到 150ms 覆盖时回退到原始最大值——短周期与
旧行为逐分一致。真正持续的偏离（整周期上臂漂移、持续高速）覆盖远超 150ms，
扣分与修复前相同（测试锁定：持续惩罚 40 → 稳定性 ≈60；持续 ≈312°/s →
稳定性 ≈96）。三条路径（锤式 per-side、前平举 per-side、通用周期）共用。

## 4. 问题文案按动作族（poseFeedback）

根因：`POSE_ISSUE_COPY.unstable_movement` 是下肢文案（「支撑或落地不稳 /
不赶时间，慢一点，站稳了再来」，高亮髋/膝/踝），对所有动作通用——弯举的
实时提示与结算「下一个小目标」里出现的就是这句，与问题（上臂控制）无关；
`poor_coordination` 的「让手脚一起动」同理。

修复：新增 `poseIssueCopy(issue, type)` 解析器。上肢动作族（弯举类、前平举、
侧平举类、推举类、划船类、卧推类、三头类、反向飞鸟，名单在
`companionCopy.UPPER_BODY_EXERCISE_TYPES`）的两个问题改上肢口径：

- `unstable_movement` → 「手臂摆动偏大 / 慢一点，肘贴紧身体，把这一下做稳」，
  高亮 [11,12,13,14]（肩、肘）；
- `poor_coordination` → 「两边节奏没对齐 / 慢一点，让两只手一起起、一起落」，
  高亮 [15,16]（腕）。

其余动作与其余问题类型原文一字不改。接入点：extended / plan / 基础三个
tracker 的消息组装、结算页 Summary（下一个小目标 + 下次可以关注，类型取
`result.exerciseType`）、Workout 的语音纠正决策（`decideCorrectionCue` 新增
可选 type 参数）。

## 5. 入镜文案诚实化（companionCopy）

front_raise 的必需关节是 [11,12,13,14,15,16,23,24,0]——头 + 上半身 + 髋，
没有膝踝，但 `COPY_NOT_SEEN` / `COPY_FRAMING` 都说「让我从头看到脚」，
要求超过了实际门。新增上肢变体 `COPY_NOT_SEEN_UPPER` / `COPY_FRAMING_UPPER`
（「让我看到你的头和上半身」）与选择器 `notSeenCopyFor(type)` /
`framingCopyFor(type)`，接入：三个 tracker + adaptive 包装的未见文案、
Workout 准备页的站位引导（该处有 exerciseType，按族选择）。未接入：
`framingFeedback` 的逐关节提示（按必需关节逐个点名，不含全身措辞）与
`POSE_ISSUE_COPY.out_of_frame` 的动作句（属问题文案表，本轮未在第 4 项
范围内）——留作后续。
