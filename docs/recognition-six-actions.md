# 新增六种 AI 动作

2026-10-30。独立 AI 训练由四种增至十种，训练入口切换「基础4种／新增6种」。新六种同时用于指定动作的计划与自由训练，均为试用。

| 类型 | 标准形式与拍摄 | 动作库 ID |
| --- | --- | --- |
| `hammer_curl` | 站姿双臂同时锤式弯举，正面略侧身，肩肘腕髋入镜 | `exdb:0313` |
| `front_raise` | 双臂同时前举，斜侧面、头部和双手清晰；方向不可靠时提示调整 | `exdb:0310`、`exdb:0834` |
| `triceps_kickback` | 屈髋俯身、双臂同时向后伸肘，斜侧面 | `exdb:0333`、`exdb:1741`、`exdb:0420` |
| `romanian_deadlift` | 双手各一铃、膝微屈、髋后移，斜侧面全身；不要求触地 | `exdb:1459` |
| `glute_bridge` | 徒手仰卧屈膝、平地双脚支撑，降低摄像头从侧面拍摄 | `exdb:3013` |
| `standing_leg_curl` | 徒手直立，脚跟向后抬起再放回，侧面／斜侧面全身 | `exdb:0795` |

每个完整回位算一次。后屈腿左右合计目标 20 次，可连续练一侧；一次动作固定跟踪侧，左右数量独立于评分保存。交替弯举、单臂臂屈伸、负重臀桥等未支持变式继续手动记录。库总数仍为 1,329，未新增重复条目，摄像头筛选匹配 20 个指定条目（含已有能力）。

## 识别与数据

- 共用本地姿态模型和识别器工厂。新六种采用五帧中值平滑、两秒起始姿势校准、峰值与回位滞回。原四种和已有六类计划识别器的行为、阈值保持原样。
- 使用实际视频比例；前平举必须有可靠世界坐标与身体前向，侧举不计入。硬拉检查屈髋、膝部和脚位；臀桥检查髋升高及肩脚固定支撑；后屈腿排除向前抬大腿及半程换侧。
- 暂停、刷新或持续遮挡丢弃未完成动作，已完成次数与累计评分保留。评分依次为幅度 35%、控制 25%、姿态 20%、协调 20%；无法可靠评分可计数但显示「无法评分」，评分不阻止计数。
- 前后端元数据共用 `server/src/gym/new-recognition.json`。新动作写入要求请求头 `X-MoveMate-Recognition-Version: 2`；普通请求与离页后台保存均携带。旧页面被明确要求刷新；未知类型不兜底为深蹲。
- 沿用运动／计划 API、事务和唯一结算流水，不新增表。新动作评分累计次数不得大于总次数；后屈腿左右合计必须等于总次数。自定义与导入数据不能授予识别能力，进行中计划快照不自动升级。
- 独立真实识别每次 2 XP；演示 0 XP，不解锁；计划仍仅按有效分钟结算。新动作不累计到深蹲统计或任务。

## 验收范围

纯函数合成关键点覆盖完整／连续循环、半程、遮挡、低帧率、画面比例、暂停与恢复、方向排除、侧别恢复及评分差异。后端覆盖协议、精确映射、账号隔离、演示零 XP、重复结束与计划唯一结算；Workers 验证实际运行时与侧别保存。

浏览器验收使用项目外的隔离数据库、明确标注的关键点回放及演示，不把它们称为实拍。真实摄像头逐动作质量、真人语音和 BLE 本轮未验收；新动作持续显示「试用」。无法测量哑铃重量、可靠验证握法或判断脊柱健康，评分也不代表专业认证。

部署与回滚沿用 [Cloudflare 部署说明](cloudflare-deployment.md)。本批仅更新代码与静态资源，不重置账号、训练或成长数据；保留已有在线版本用于代码回滚。

回滚修复版本仍需保留新增类型、协议校验和读取兼容；已有新动作进行中时，不应直接回退到把未知类型当成旧动作的页面。
