## 浏览器实际操作

- 创建并编辑全身模板，调整目标和休息，保存周六安排；计划草稿刷新后恢复，保存后以服务器版本为准。
- 两组手动训练：开始 → 完成本组 → 休息 → 下一组 → 暂停 → 刷新恢复 → 结束。有效时长 **104 秒，1 XP**。
- 四动作关键点回放：深蹲、开合跳、高抬腿左右配对、俯卧撑各自动完成一组；动作切换共用设备连接。另验证连续三次深蹲同步期间不重置校准，18 秒完成三次。
- 回放页面明确显示“关键点回放验收”，使用测试环境的合成视频和模型接口；并非实拍。设备统计显示一条流、一个模型，结束后均释放。
- 模拟暂停和结束已提交但响应丢失：显示未确认状态，保留原操作，联网后读取并恢复；新版恢复后无残留错误提示，记录 52 秒、0 XP，未重复结算。
- Strong CSV 经预览导入一条历史，明确 0 XP；其余格式、重复导入及未知动作映射由后端回归覆盖。保存身体记录和目标体重，分析页显示真实记录。
- IAB 与 Chrome 两个普通账号完成加入、共同计划、聊天、签到、确认到场、活动开始和各自开始本组。浏览器连接中断后由两个隔离登录会话继续验收；成员提前结束先显示待结算，发起人结束活动后，成员 **1792 秒／29 XP**、发起人 **1835 秒／30 XP**。活动进入签到窗口使用独立测试数据库的时钟夹具，未修改正式规则或生产数据。
- 检查 390、768、1440px 下的训练入口、计划、编辑、动作库、分析、身体、数据管理及逐组历史：有实际内容，无横向溢出或框架错误覆盖层。手机训练的完成、暂停和结束按钮可达；现有独立摄像头电脑布局未改。
- 浏览器故障注入中的 503 为预期测试错误；正常预览页无相关控制台异常。

## 已明确的验收边界

- 真实摄像头动作质量、BLE 和真人同时有声对话本轮未重测，不用关键点回放代替实拍。

- 训练分析针对计划与导入的逐组记录；原独立动作、个人计时及组局运动仍可从全部运动记录查看。
