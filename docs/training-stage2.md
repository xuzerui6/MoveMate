# 训练能力融合第二阶段

独立实现训练能力，沿用动伴账号、白绿界面、Cloudflare SQLite、聊天与成长系统。没有复制 openGym 代码、翻译或受限媒体。既有深蹲、开合跳识别器和电脑摄像头布局保持不变。

## 入口与使用

| 入口 | 能力 |
|---|---|
| `/train/free` | 先选动作再创建自由训练；按账号保留未开始草稿 |
| `/train/workout/:id` | 手动／四动作记组；添加、复制、替换、排序、移除及撤销；休息增减、跳过；可选 RPE/RIR、备注、声音及常亮 |
| `/train/plans` | 模板、可编辑建议草稿；结束后的训练可另存新计划 |
| `/train/plans/:id/edit` | 周计划／循环、逐动作进阶覆盖；建议须确认后保存 |
| `/train/schedule` | 账号时区的一周安排、单次调课／跳过／恢复；目标日已有安排并列显示 |
| `/train/library` | 中文术语、原文、拥有器械、主练／辅助肌群；自定义动作编辑与归档 |
| `/train/stats` | 逐动作历史、负重／次数／训练量／估算 1RM 曲线、一年日历、肌群覆盖、配重计算 |
| `/train/settings` | kg/lb、时区、拥有器械、可选用力程度及 PWA 安装入口 |
| `/train/data` | 版本 2 完整 JSON、CSV、分批预览／映射／冲突选择／去重／断点继续 |

训练内的调整只修改本次快照，不覆盖来源计划。已经开始的组不可删除或替换，须先完成或跳过；移除只针对未开始的组，保留稳定 ID 以便撤销。

上回实际次数和负重是建议预填，不是已完成数据，确认完成后才保存。RPE/RIR 由本人填写，与识别评分分别保存、展示，不增加 XP。

## 计时、成长和同步

- 一次训练仍对应一条 `fitness + timer` 主记录。准备、休息和暂停不计时；每次结算 `floor(有效秒数 / 60)` XP。计划内摄像头仅计数，不重复发奖；独立摄像头奖励沿用原规则。
- 操作沿用事务队列、稳定组 ID、唯一 `operationId` 和版本校验。旧页面或延迟离线暂停不能覆盖新页面的训练。
- 新开始的计划／自由训练每 15 秒发送服务端时间检查点。超过 45 秒没有确认在线状态时，最多保留至上次确认的时刻；恢复先读取并暂停，不补发断线期间 XP。旧记录保留原计时兼容行为。
- 手机锁屏或浏览器后台可能停止定时器；建议保持页面前台。常亮和声音依赖浏览器支持，退出页面释放资源，不承诺系统级锁屏提醒。
- 循环只在完成当前应练训练日的全部组后推进；临时训练其他日不推进。进阶默认关闭，支持逐动作线性／双重／三级／计时覆盖。连续三次完整训练未达到各次原目标时只建议降载 10%，不自动执行。
- 重量统一按 kg 保存，界面切换单位不重写已存数据。配重只使用拥有数量的成对杠铃片，并显示差额，不改变训练目标。
- Epley 估算只用于 1–10 次、带外部负重、完成的正式组。肌肉图显示记录覆盖，均不用于自动开具训练处方或判断确定的恢复状态。

## 完整导入与离线

完整 JSON 版本 2 包含本人计划、自定义动作、历史、身体记录和设置；兼容版本 1。openGym 支持能识别的 `plans/routines`、`workouts` 和体重列表；不认识的结构会显示错误，不推测写入。

新版分批入口支持 JSON、Strong／Hevy／FitNotes CSV，文件最多 20 MB。按类型和大小拆批，每批先预览，再处理未知动作和冲突。自定义 ID 重新绑定到当前账号；冲突可保留现有或另存副本，身体记录只补空字段，采用导入设置需明确选择。服务端保存断点；浏览器按账号保存文件草稿，刷新继续，重新选择同一文件也能取回断点。

导入的历史不创建正式运动主记录或 XP 流水，不恢复摄像头评分；可保留手填用力程度、备注。未结束计时不恢复成正式计时。历史更正只重算分析，已结算 XP、原时长和识别成长保持不变。

PWA 只缓存访问过的静态资源，以及按账号区分的训练只读数据。语音、认证接口、原始图片／音视频不缓存。离线不能新建正式计时；未确认训练操作保留，联网核对后恢复。退出或切换账号清理该账号缓存与草稿；导入任务请求固定使用发起账号的会话。

## 兼容、备份与回滚

新增 `gym_schedule`、`gym_import_batches`、`gym_restore_items`；可空用力程度、备注和结构元数据存入现有组 JSON，旧记录无需补值。

本机自动检测增量表并在更新前 `VACUUM INTO` 一致备份。Cloudflare 在首次新增表前保存 `pre_gym_stage2_bookmark`；受保护的 `/api/migration/gym-backup` 可读取。实际生产书签已另外保存至项目外，本机 `demo.db` 也已备份。

发生发布问题优先回滚 Worker 代码，继续使用当前数据库。不要删除新表或覆盖新产生的数据；数据库时间恢复属于单独操作。本机继续使用原一键启动脚本。
