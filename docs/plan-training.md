# 计划训练与 openGym 能力融合

入口：训练 → 计划训练。保持现有账号、Cloudflare SQLite、组局、成长与独立摄像头训练；没有嵌入第二套应用或复制 openGym 实现。

## 使用流程

1. 从全身、上下肢、推拉腿或 5×5 模板创建个人计划，编辑训练日、每周安排或循环顺序。
2. 动作库可按中文关键词、肌群、器械、类型或收藏筛选。原文名称保留，常见动作有中文检索别名；步骤来自许可明确的文本数据。可创建仅本人可见的自定义动作。
3. 每个动作可设置组数、热身／正式／递减／休息暂停组、重量、次数、计时目标、左右侧和组后休息。同编号且连续的超级组动作按轮交替；一轮结束后休息。
4. 开始计划后先处于准备阶段，不累计有效时长。每组主动开始；完成本组后即停止计时，休息结束也不会自动开始下一组。暂停、离开与刷新保留服务端记录。
5. 四种指定徒手动作支持摄像头记组；其他动作手动记录。摄像头先准备成功再开始本组，每组重新校准，半程不计数。高抬腿按左右配对计数。改为手动会清除该组识别评分，不能冒充识别成绩。
6. 结束整次训练后才确认保存结果。网络结果不明确时保留原操作，先读取服务端，再重放同一个操作 ID；版本冲突显示错误并要求恢复同步。

## XP 与成长

- 一个计划只有一条 `fitness + timer` 运动主记录。XP = `floor(有效秒数 / 60)`；摄像头只帮助计划计数，不额外按次数奖励。
- 休息、准备和暂停不计时；后台、锁屏和刷新以服务端时间段为准。
- 独立 AI 动作训练保持每次／对 2 XP；演示保持 0 XP。
- 计划内实际识别的评分和深蹲次数可进入原有成长统计；手动、导入与历史更正不生成识别成绩。
- 历史重量和次数更正只更新训练分析，不重新计算已结算时长、成长或 XP。

## 分析、身体记录和建议

逐组记录展示实际重量、次数、计时、来源和识别均分。分析包括训练次数、外部训练量、个人纪录、周／月趋势、近 12 周日历与近 30 天肌群覆盖。外部训练量为 `kg × 次数`，每侧记录按两侧计算；热身不纳入正式训练量，徒手动作不推测体重负荷。

肌肉图只反映记录覆盖、组数与最近日期，不推断确定的恢复状态。身体记录按账号保存日期、体重、目标体重、腰／胸／臀围，可分别查看趋势，其他账号无权读取。

进阶默认关闭。开启线性、双重或三级规则后，仅根据本人的已完成计划训练生成建议，必须点击确认才保存；导入历史不触发进阶。结构建议复用原 HTTP 陪练；未配置或请求失败明确标为本地规则，不自动调整计划。

## 共享与数据

健身活动的发起人可在开始前附上训练日快照。共享动作目标，不共享私人负重；成员须正常签到，活动开始后各自开始、休息和记录。提前结束显示待结算，活动结束统一按原到场条件结算，并关闭尚未结束的计划。

- 分享计划使用 `movemate-plan` JSON，自定义动作导入时重建为接收账号所有，重复文件不重复创建。分享默认清零个人负重；全部训练日可打印／存为 PDF。
- 支持 openGym JSON 训练历史、Strong／Hevy／FitNotes CSV，以及动伴 JSON 历史；未知动作必须先选择映射。可选择 kg／lb，日期须可解析，预览后才写入。
- 每批最大 1.8 MB、100 次训练、2000 组；重复训练指纹去重。导入不创建奖励主记录，不补发 XP、不解锁装备。
- 本人 JSON 导出包括计划、自定义动作、逐组历史和身体记录；CSV 为已完成组的表格数据，转义公式开头文本，不含账号密码或服务令牌。
- 草稿和未确认操作按账号分开缓存；服务端以账号归属、版本和唯一操作 ID 为准。

## 存储、发布和回滚

增量增加 `gym_*` 表，原运动、XP、账号、活动和聊天表不替换。SQLite 本机首次升级前自动 `VACUUM INTO` 备份；Cloudflare 首次添加计划表前取得 PITR 书签，保存为受迁移密钥保护的 `/api/migration/gym-backup`。恢复窗口见 [Cloudflare SQLite PITR 文档](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)。

沿用 `start-demo.bat`，本机自动编译及初始化。发布使用 `cloudflare` 中的 `npm run deploy:preview`，验收后 `npm run deploy`。线上出现代码问题优先使用已有部署回滚命令恢复 Worker 版本，保留数据库及新增数据；开放新写入后不要用旧数据库快照覆盖现有记录。备份书签和检查结果保存在项目外，密钥与运行数据不进入 Git。
