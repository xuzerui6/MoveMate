# 摄像头识别时序与稳定性改进（协议 v6）

本批为识别链路改进与对照测试能力。自 2026-11-04 起（见文末“自动选择策略、免定时校准与 iOS 兼容”一节），新版自适应已改为对**新记录自动启用**；准备区保留一个仅作用于新记录的改选旧版入口（本机偏好），已有记录仍固定其保存的策略。**基础四种的真人对照已在 iPhone Safari 与 Windows Chrome 实测（维护者回报识别准确，未逐组记录计数），力量动作逐项与量化对照仍未完成，不宣称量化真人准确度**；自动启用是产品策略变更，不是真人验收结论。

## 使用与范围

进入 AI 动作训练，或计划／自由训练的待开始摄像头组，策略由系统自动决定（`selectRecognitionStrategy`）：已有记录／已开始的组使用其保存的策略；新记录在动作属于自适应支持范围、且浏览器具备模型哈希校验能力（Web Crypto）时使用新版自适应，否则用旧版。准备区的“识别方式（新记录）”可把本机偏好改选为旧版，强制之后的新记录用旧版；偏好只存本机，不上传、不写入记录。进行中的运动／组固定策略；刷新按服务端记录恢复。新版先测量模型性能，准备不再要求定时姿势校准：模型就绪且首个可用帧到达后即开始识别，第一个完整动作开始计数，准备阶段不计正式训练时间。失败可重试、暂停后使用 Lite 重新准备；计划内可按现有流程转手动，独立训练可结束后改用个人计时。

新版自适应支持范围（共 20 种）：基础四种，哑铃／杠铃／反握／坐姿弯举、锤式弯举，肩推／坐姿中立握肩推，哑铃／杠铃俯身划船，卧推／上斜卧推，罗马尼亚／杠铃硬拉，以及高脚杯／杠铃前蹲／后蹲。其余动作沿用旧链路。动作 ID、支持形式、识别阈值与奖励不扩展。

## 实现

- Full float16/1、Lite float16/1 固定模型随站点托管，SHA-256、大小、来源见 `client/src/features/motion/lib/pose-models.json`。构建及开发启动校验；浏览器加载后再次校验，不自动下载第三方 CDN。保留 Apache-2.0 许可证及第三方说明。
- 模型选择：iPhone／iPad 直接在主线程运行 Lite，不做 Full 探测（`usesMainThreadLite`）；其他设备先 Worker GPU → Worker CPU → Lite 主线程 GPU／CPU 降级。初始化包含真实首帧探测；首帧有较长编译预算，失败关闭对应 Worker 后尝试下一方式。固定版本 SDK 的 WASM 加载器使用 importScripts，Worker 编译为 classic IIFE。
- Full 连续至少两秒实际吞吐 ≥15 FPS 且 P95 ≤200ms 才保留，否则准备期切 Lite；Full 探测失败或超时（12 秒）同样自动降为 Lite，不需要用户手动重试。训练中不会自动换模型。
- 一帧在途，繁忙时丢弃新采样机会，无积压。采集媒体时间映射到单调时钟，帧 ID／运行实例隔离。重复、乱序、超过250ms、旧实例返回结果不推进计数。
- 优先视频帧回调；回调长期不触发时转动画帧调度，并通过解码帧编号去重。备用调度的媒体时间是浏览器提供的近似值，并非摄像头硬件曝光时间。主线程 Lite 上限15 FPS。
- 新链路使用一层时间感知滤波；原引擎五帧缓冲只在新版关闭，旧链路保留。自适应不再要求稳定起始姿势两秒／15 个样本的定时校准：起始姿势在首个可用帧即确认（armOnStart），仍检查关节、入镜、人体尺度与原动作起始要求；不学习半程动作降低标准。旧链路的两秒校准不变。
- 必要关节短暂置信度波动最多冻结200ms，不推进阶段。持续丢失、出画、位置突变、尺寸或二维／三维依据切换丢弃半程并要求回到起始姿势，保留完整次数及评分累计。三维依据另查世界坐标关节置信度、骨段比例及连续性。
- 深蹲自适应支持单侧跟踪：仅一侧可见时按跟踪侧计数，跟踪侧短暂遮挡冻结、持续丢失不拼接半程；关键点不足时只计数不评分，评分按完整周期（含回程）计算。
- 苹果设备上预览改由原生 video 元素呈现（Canvas 只叠加骨骼）；帧回调的媒体时间戳停滞时转动画帧调度，准备阶段视频暂停时自动重试播放一次，避免预览黑屏／假死。
- 连续低于8 FPS三秒或长时间无结果冻结并释放识别资源，调用现有暂停流程。页面转后台也冻结；暂停失败仍由现有状态核对和重试恢复。计划页等待控制请求结束后尝试暂停一次，失败不无限重试。
- 评分与计数独立；信息不足时完整次数可保留而不生成虚构评分。后端 v6 支持新版评分次数少于完成次数；仍禁止超出次数、策略改变及旧页面覆盖新版统计。
- 模型、模式、有效帧率、P95、阶段、原因仅本机诊断；这些不是“识别准确率”。退出／账号切换关闭模型、Worker、相机及未完成请求。取消后迟到的权限流也立即停止。

## 数据与兼容

仅在既有 session.metrics／组 data JSON 保存 `recognitionStrategy: legacy | adaptive-v1`。不新增表或字段，不迁移历史记录。新版写入要求 `X-MoveMate-Recognition-Version: 6`；旧记录缺少策略时视为 legacy。新请求不能更改活动记录策略，恢复仍使用原动作、来源、次数及累积评分。重复结束沿用唯一 XP 流水，独立2 XP／次，计划按有效分钟计算，演示0 XP。

## iPhone Safari 准备失败后续修复（2026-11-01）

用户反馈：iPhone Safari有画面，等待后出现“摄像头或模型加载失败”；未取得该设备的具体异常文字，不能认定所有原因都已定位。

已确认的程序问题：旧15秒准备倒计时从模型初始化后即开始，仍包含Full性能测量以及性能不达标时的Lite下载／初始化。慢设备可能在真正稳定校准前耗尽预算；超时同时被误称为摄像头／模型加载失败。

修复内容：

- 性能测量与稳定校准分开计时，降级下载／初始化完成后才开始30秒校准预算。Full没有持续结果时单独给出性能测量失败；模型下载20秒超时可恢复，不无限等待。
- 明确区分校准未完成、性能未达要求与加载失败，直接展示具体原因。没有建立推理通道时不虚标“Worker GPU”。
- 等待真实首帧尺寸／readyState，而不是仅凭play()返回就开始Worker探测；等待可取消并有明确超时原因。
- 新链路的video源保持最小可渲染区域，避免display:none影响WebKit合成／帧回调；画面仍由原Canvas展示，电脑摄像头布局不变。参照[WebKit帧回调限制记录](https://bugs.webkit.org/show_bug.cgi?id=282797)，该兼容调整尚需真机复测。
- 新版失败后提供“使用Lite兼容模式重试”，明确跳过Full及Worker，在主线程运行Lite并限频；初始化也校验首帧，GPU失败可换CPU。旧版默认策略不变，不降低计数标准，不改XP。

## 减少重复准备等待（2026-11-01）

针对“每次开始都校准很麻烦”，本批减少等待，不移除入镜与完整动作标准：

- 首次Full性能测量与稳定起始姿势检查并行。两项均通过、且当前仍在起始阶段，才创建／恢复正式记录；Full降为Lite时仍重置起始姿势检查。
- 新版同一次运动／同一计划组短暂暂停时，复用仍开启的相机与模型，以约10 FPS在本地自动准备。用户回到起始姿势后，原两秒稳定检查提前完成，界面显示“起始姿势已准备好，可直接继续”。
- 点击继续仅在同一记录、同一模型／摄像头会话、当前起始阶段、最近结果≤200ms且有效帧率≥8时复用。更换运行实例编号，拒绝暂停前返回的旧结果；不带入暂停期间的半程动作。

## 哑铃弯举反馈的真因与模型加载修复（2026-11-05）

维护者回报 iPhone 上哑铃弯举「识别不太好用」（双臂同时举），当晚补充截图证实：失败发生在识别开始之前——准备页红框「模型加载失败：模型下载超时」。即 Lite 模型（5.78MB）未能在原 20 秒预算内下载完成，计数环节根本没有启动；此前对弯举计数口径的猜测（双肘门槛）不是本次反馈的原因，不据此修改计数口径。

根因有三：模型文件每次加载都重新下载（`/pose/*` 此前只有 `max-age=0, must-revalidate` 的缓存头）；下载超时固定 20 秒且无重试；下载成功后不留本地副本，换个网络环境就要重来。

修复（均已通过全套验证）：

- 加载器把校验通过的模型字节写入本机 Cache Storage（`pose-models-v1`），每次读回都按 `pose-models.json` 的 SHA-256 复验，校验不过即删除并重新下载——后续打开同一动作不再走网络；
- 网络下载超时 20 秒放宽到 60 秒，超时／网络错误自动重试一次（大小与完整性校验失败不重试，立即报错）；
- `/pose/*`（模型与 WASM）在 Worker 侧改为 `Cache-Control: public, max-age=2592000`（30 天）。

新增回归测试 2 项（本机缓存命中后断网仍可加载、缓存损坏自动弃用重下；瞬时网络失败重试一次、大小校验失败不重试）。客户端仓库测试 291/291、tsc、服务端 103/103＋构建、Cloudflare 31/31＋类型检查全绿。真人复验状态：待维护者在 iPhone 上部署后重试哑铃弯举确认（首次仍需完整下载一次，之后应为本地加载）。
