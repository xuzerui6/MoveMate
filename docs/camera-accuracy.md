# 摄像头识别时序与稳定性改进（协议 v6）

本批为识别链路改进与对照测试能力，**尚未完成 iPhone Safari／Windows Chrome 真人计数对照，不宣称真人准确度提升**。旧版仍为所有动作的默认策略；新版须在准备页明确选择“新版自适应 · 对照测试”。已有人体验证组合列表当前为空。

## 使用与范围

进入 AI 动作训练，或计划／自由训练的待开始摄像头组，在“识别策略”选择旧版或新版。进行中的运动／组固定策略；刷新按服务端记录恢复。新版先测量模型性能，再稳定校准，均不计正式训练时间。失败可重试、暂停后使用 Lite 重新准备；计划内可按现有流程转手动，独立训练可结束后改用个人计时。

新版对照范围：基础四种，哑铃／杠铃／反握／坐姿弯举、锤式弯举，肩推／坐姿中立握肩推，哑铃／杠铃俯身划船，卧推／上斜卧推，罗马尼亚／杠铃硬拉，以及高脚杯／杠铃前蹲／后蹲。其余动作沿用旧链路。动作 ID、支持形式、识别阈值与奖励不扩展。

## 实现

- Full float16/1、Lite float16/1 固定模型随站点托管，SHA-256、大小、来源见 `client/src/features/motion/lib/pose-models.json`。构建及开发启动校验；浏览器加载后再次校验，不自动下载第三方 CDN。保留 Apache-2.0 许可证及第三方说明。
- Worker GPU → Worker CPU → Lite 主线程 GPU／CPU 降级。初始化包含真实首帧探测；首帧有较长编译预算，失败关闭对应 Worker 后尝试下一方式。固定版本 SDK 的 WASM 加载器使用 importScripts，Worker 编译为 classic IIFE。
- Full 连续至少两秒实际吞吐 ≥15 FPS 且 P95 ≤200ms 才保留，否则准备期切 Lite。训练中不会自动换模型；重新选择需要暂停并重校准。
- 一帧在途，繁忙时丢弃新采样机会，无积压。采集媒体时间映射到单调时钟，帧 ID／运行实例隔离。重复、乱序、超过250ms、旧实例返回结果不推进计数。
- 优先视频帧回调；回调长期不触发时转动画帧调度，并通过解码帧编号去重。备用调度的媒体时间是浏览器提供的近似值，并非摄像头硬件曝光时间。主线程 Lite 上限15 FPS。
- 新链路使用一层时间感知滤波；原引擎五帧缓冲只在新版关闭，旧链路保留。稳定起始姿势至少两秒、15个样本；检查关节、入镜、人体尺度、位置稳定与原动作起始要求，不学习半程动作降低标准。
- 必要关节短暂置信度波动最多冻结200ms，不推进阶段。持续丢失、出画、位置突变、尺寸或二维／三维依据切换丢弃半程并重校准，保留完整次数及评分累计。三维依据另查世界坐标关节置信度、骨段比例及连续性。
- 连续低于8 FPS三秒或长时间无结果冻结并释放识别资源，调用现有暂停流程。页面转后台也冻结；暂停失败仍由现有状态核对和重试恢复。计划页等待控制请求结束后尝试暂停一次，失败不无限重试。
- 评分与计数独立；信息不足时完整次数可保留而不生成虚构评分。后端 v6 支持新版评分次数少于完成次数；仍禁止超出次数、策略改变及旧页面覆盖新版统计。
- 模型、模式、有效帧率、P95、阶段、原因仅本机诊断；这些不是“识别准确率”。退出／账号切换关闭模型、Worker、相机及未完成请求。取消后迟到的权限流也立即停止。

## 数据与兼容

仅在既有 session.metrics／组 data JSON 保存 `recognitionStrategy: legacy | adaptive-v1`。不新增表或字段，不迁移历史记录。新版写入要求 `X-MoveMate-Recognition-Version: 6`；旧记录缺少策略时视为 legacy。新请求不能更改活动记录策略，恢复仍使用原动作、来源、次数及累积评分。重复结束沿用唯一 XP 流水，独立2 XP／次，计划按有效分钟计算，演示0 XP。

## iPhone Safari 准备失败后续修复（2026-11-01）

用户反馈：iPhone Safari有画面，等待后出现“摄像头或模型加载失败”；未取得该设备的具体异常文字，不能认定所有原因都已定位。

已确认的程序问题：旧15秒准备倒计时从模型初始化后即开始，仍包含Full性能测量以及性能不达标时的Lite下载／初始化。慢设备可能在真正稳定校准前耗尽预算；超时同时被误称为摄像头／模型加载失败。

修复内容：

- 性能测量与稳定校准分开计时，降级下载／初始化完成后才开始30秒校准预算。Full没有持续结果时单独给出性能测量失败；模型下载20秒超时可恢复，不无限等待。
- 明确区分校准未完成、性能未达要求与加载失败，直接展示具体原因。没有建立推理通道时不虚标“Worker GPU”。
- 等待真实首帧尺寸／readyState，而不是仅凭play()返回就开始Worker探测；等待可取消并有明确超时原因。
- 新链路的video源保持最小可渲染区域，避免display:none影响WebKit合成／帧回调；画面仍由原Canvas展示，电脑摄像头布局不变。参照[WebKit帧回调限制记录](https://bugs.webkit.org/show_bug.cgi?id=282797)，该兼容调整尚需真机复测。
- 新版失败后提供“使用Lite兼容模式重试”，明确跳过Full及Worker，在主线程运行Lite并限频；初始化也校验首帧，GPU失败可换CPU。旧版默认策略不变，不降低计数标准，不改XP。

验证：前端258项通过（新增3项首帧等待／取消／超时）；隔离浏览器模拟Full测量后再延迟12秒加载Lite，仍能校准后开始；有效画面但姿势不对时显示校准错误且无新记录；Lite兼容重试不创建Worker并可结束保存。实际MediaPipe固定图片推理及资源释放通过，非真人计数验收。iPhone Safari真机结果仍待用户复测，不能用Chrome中的兼容模拟替代。

后续修复预览版本 `66725f28-59bc-4177-9736-5f23ba010536`：健康与v6恢复接口、43个原映射、390／768／1440px准备页通过；原四动作回放、暂停／恢复、计划记组与结束、低帧率暂停、权限／模型失败回归通过。正式修复版本 `ed825d5c-8340-42f9-a161-af341337d8c9`，继续legacy默认。没有更改服务端、数据库、XP或识别阈值。

## 减少重复准备等待（2026-11-01）

针对“每次开始都校准很麻烦”，本批减少等待，不移除入镜与完整动作标准：

- 首次Full性能测量与稳定起始姿势检查并行。两项均通过、且当前仍在起始阶段，才创建／恢复正式记录；Full降为Lite时仍重置起始姿势检查。
- 新版同一次运动／同一计划组短暂暂停时，复用仍开启的相机与模型，以约10 FPS在本地自动准备。用户回到起始姿势后，原两秒稳定检查提前完成，界面显示“起始姿势已准备好，可直接继续”。
- 点击继续仅在同一记录、同一模型／摄像头会话、当前起始阶段、最近结果≤200ms且有效帧率≥8时复用。更换运行实例编号，拒绝暂停前返回的旧结果；不带入暂停期间的半程动作。
- 暂停中的完整动作也不增加次数、评分、服务器有效时长或XP。主动准备仅用于当前页面的明确暂停状态；断网、状态待确认、结束等状态继续冻结。离开、后台、结束、切账号仍释放资源。
- 新开训练、刷新、换动作／计划组、模型切换、移动或出画等仍按原规则重新检查。不在本机存储人体基线、影像或关键点，不用上一场训练的身体数据替代本次检查。旧版默认不变。

验证：前端265项通过，新增准备复用／暂停半程拒绝／暂停动作不计数测试。隔离回放中独立训练暂停续练约48ms、计划续练约46ms；Full从第一帧到可开始约2.8秒（包含并行性能测量与姿势检查）。这些是本机模拟输入／接口耗时，不能当作iPhone或真人准确度结果。基础四种计数、刷新恢复、低帧率暂停、计划记组、权限与模型失败、退出释放回归通过。
